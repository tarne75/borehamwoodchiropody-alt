# Borehamwood Chiropody & Podiatry — site rebuild

A static rebuild of `borehamwoodchiropody.co.uk`, ready to deploy to GitHub Pages.
Zero dependencies, zero build step. Open `index.html` in a browser and it works.

See **[BRAND.md](BRAND.md)** for the palette, logo, typography and contrast rules.

---

## 1. What this replaces

The original site ran on the itseeze/Spoton.net website builder. It was 12 separate
pages (10 content, 2 legal) carrying 79KB of generated CSS, a bespoke responsive-image runtime, a
cookie-consent framework, Google Analytics (both GA4 and a Universal Analytics
property that stopped collecting data in 2023), and a layout system built on
utility classes like `w-flex-basis-1-xs wFlexBasis1Xs`.

This rebuild is a single page of hand-written HTML, one 35KB stylesheet, one 18KB
script, and no third-party JavaScript at all.

### Content mapping

Every page of the original is accounted for. Nothing was dropped.

| Original page | Where it went now |
|---|---|
| Home (welcome + K Laser) | Hero, `#welcome` split, `#laser` |
| About Us | `#about` — merged with the practitioner bio from the home page, plus the qualifications panel |
| Techniques | `#treatments` — six cards |
| Services › Conditions Treated | `#conditions` — data-driven grid |
| Services › Nail Fungus Treatment | Folded into `#laser` |
| Services › Chiropody Products | Products section (after `#about`) |
| Fees | `#fees` — data-driven table |
| FAQs | `#faqs` — data-driven accordion |
| Testimonials | `#reviews` |
| Contact Us | `#contact` — form, details card, opening hours, map |
| Privacy | `privacy.html` |
| Cookies | `cookies.html` |

### Content changes, and why

Wording was retained. Where it changed, it was for one of these reasons:

- **Spelling and grammar.** The original had a significant number of typos —
  `Tecniques`, `Psyciatric`, `domicillary`, `fugal infection`, `plantar fascitis`,
  `keep interest` (for *keen*), `clear fo fungus`, `an becomes painful`. All corrected.
  Tone and phrasing were left alone.
- **De-duplication.** Edwina's biography appeared in two different versions on the
  home page and About page. They were merged into one, keeping every unique fact.
- **The nail fungus page** duplicated most of the conditions and K Laser copy. The
  unique material (the onychomycosis explanation, the treatment description, the
  bullet list) was kept; the repetition was not.
- **The accreditation badge was reinstated as text, not as the original image.** The old
  About page carried a 318×159px bitmap reading "The COLLEGE of PODIATRY / The SOCIETY of
  CHIROPODISTS & PODIATRISTS" with `www.scpod.org`, followed by a bare `12282`. Both of
  those names are dead: the Society name was retired in June 2018 and the College became
  the **Royal College of Podiatry** in July 2021. Reproducing a superseded third-party
  logo on a new site is worse than the gap it fills, so `#about` now carries a
  `.creds` panel using current names, with 12282 labelled as what it is — an RCPod
  membership number, not an HCPC one. The prose and the hero trust strip were updated to
  "Royal College of Podiatry" to match.
- **"Governing body" corrected to "professional body."** The original described the College
  as "our professional governing body". It isn't: the Royal College of Podiatry is the
  professional body and trade union, and the HCPC is the statutory regulator. On a
  healthcare site that distinction is worth getting right.
- **Duplicate testimonial removed.** "She knows every thing about verrucae" and the
  laser testimonial were both retained; nothing else was cut.

### Things deliberately left out

- **Google Analytics.** Both properties. The UA property has not collected data since
  July 2023. If you want analytics back, add a privacy-friendly analytics script and
  update `cookies.html` — which currently, accurately, states the site sets no cookies.
- **The cookie consent banner.** Not needed. The site sets no cookies of its own, so
  there is nothing to consent to. Re-adding analytics would change that.
- **The Covid information page**, which was empty on the original.
- **`updates.atom`**, an unused RSS feed generated by the old builder.

### Sections and anchors

`#top` · `#treatments` · `#laser` · `#conditions` · `#fees` · `#about` · `#reviews`
· `#faqs` · `#contact`

The header nav resolves to these anchors. Adding a section means adding the `<section
id="…">` and a matching `<li><a href="#…">` — the scrollspy picks it up automatically
with no JS changes.

## 3. Platform features used

The brief asked for modern platform features in place of libraries. Specifically:

| Feature | Where | Replaces |
|---|---|---|
| `<dialog>` + `showModal()` | Image lightbox | A lightbox library. Focus trap, Esc-to-close, background inerting and the backdrop are all native. |
| `<details>` / `<summary>` | FAQ accordion | Accordion JS. Keyboard accessible for free. |
| `IntersectionObserver` | Scroll reveals, scrollspy, sticky-header state | Scroll event listeners. No layout thrash, no throttling needed. |
| `ResizeObserver` | Keeps `--header-h` in sync with the real header height | Hardcoded scroll offsets that break when the header wraps. |
| CSS custom properties | The whole design system | A preprocessor. |
| `clamp()` | Every type size and all spacing | Typography breakpoints. There are none in the stylesheet. |
| `color-mix()` | Tints, hover borders, focus rings | Hand-picked tint hex codes that drift from the brand colour. |
| `svh` | Hero min-height | `vh`, which is cropped by mobile browser chrome. |
| `aspect-ratio` | All images | Padding-hack wrappers. Also prevents layout shift. |
| `:user-invalid` | Form validation styling | JS-driven error classes. Only styles a field after the user has interacted with it. |
| `clip-path` transition | Mobile menu | A height animation, which cannot be GPU-accelerated. |

## 4. The data layer — this is the phase 2 hook

Four sections render from data rather than hardcoded markup: **conditions treated**,
**fees**, **FAQs** and **opening hours**.

Phase 1 (now) reads from arrays in `assets/js/data.js`. Phase 2 reads the same shapes
from published Google Sheets. The mechanism follows the pattern used on
`karatekidshemel.co.uk` and `pottersbargarage.co.uk`: a hand-rolled CSV parser, `fetch`,
no library.

### How to switch a section to a Google Sheet

1. Build a sheet whose header row matches the column names in the table below.
2. **File → Share → Publish to web → (select the tab) → CSV → Publish.**
3. Paste the resulting URL into the matching `url` field in `data.js`.

That's the whole change. The `rows` array stays where it is and becomes the fallback
if the sheet is unreachable, so a Google outage degrades to the current content rather
than to an empty section.

```js
conditions: {
  url: '',        // ← paste the published CSV URL here
  rows: [ /* … stays as the fallback … */ ]
}
```

### Expected sheet columns

| Dataset | Columns |
|---|---|
| `conditions` | `name`, `description`, `category`, `icon`, `order`, `status` |
| `fees` | `group`, `treatment`, `price`, `note`, `order`, `status` |
| `faqs` | `question`, `answer`, `order`, `status` |
| `hours` | `day`, `open`, `close`, `note`, `order`, `status` |

Conventions across all four:

- **Header matching is case-insensitive and order-independent.** Columns can be
  rearranged in the sheet without touching code.
- `status` set to `hide` removes a row without deleting it.
- `order` is a number; rows sort ascending. Values are spaced by 10 so a row can be
  inserted between two others without renumbering.
- `icon` (conditions only) is a key from the `ICONS` map in `main.js`. An unrecognised
  value falls back to a neutral dot rather than rendering nothing.
- `fees.group` controls table grouping — groups appear in order of first use, and a
  new group name creates a new panel with an icon chosen by keyword.
- `faqs.answer` splits on a blank line to make a second paragraph.
- `hours`: leave `open` and `close` blank for a closed day; `note` overrides both.

### How the rendering responds to data length

This was an explicit requirement. Neither grid nor table assumes a row count:

- **Conditions** render into a CSS grid of three equal columns (two at ≤980px, one at
  ≤620px). Eleven rows produce four rows of cards, the last one partly filled — adding
  a twelfth completes it with no code change.
- **Fees** render one row per data point, grouped into panels. There is no fixed
  number of rows or groups anywhere in the markup or CSS.

### Escaping

All values from the data layer pass through `esc()` before insertion. A stray `<` in a
sheet cell renders as text rather than breaking the page. Do not bypass this if you add
a renderer.

## 5. The contact form

Posts to **Formspree** at `https://formspree.io/f/xwvndkow`.

Submission is intercepted so the user stays on the page: `fetch` with
`Accept: application/json`, then a success or error message in `#formStatus`. If JS is
unavailable the form still submits natively to Formspree — the `action` and `method`
attributes are real.

- The `_gotcha` field is a honeypot. Formspree drops any submission where it is filled;
  the client checks it too. It is off-screen rather than `display:none`, which some
  bots detect.
- A consent checkbox is required and posts as `consent`.
- Failure messaging gives both phone numbers rather than asking the user to try again.

## 6. Performance

| | |
|---|---|
| Initial page weight | **~200KB** (HTML 41KB + CSS 34KB + JS 18KB + data 8KB + hero 101KB) |
| Requests before paint | 4 local + 1 Google Fonts stylesheet |
| Third-party JS | none |
| Full page, all images loaded | ~440KB |

What keeps it there:

- All photography converted from the original JPEG/PNG to **WebP**, resized to the
  largest size actually displayed. The hero dropped from 200KB to 101KB.
- Every image below the fold is `loading="lazy"`; the hero is `fetchpriority="high"`
  and preloaded.
- Every `<img>` carries explicit `width`/`height`, and CSS sets `aspect-ratio`, so
  cumulative layout shift is zero.
- Icons are inline SVG. No icon font, no sprite request.
- The map is an `<iframe loading="lazy">` — Google is not contacted until the user
  scrolls to the contact section.
- One font family, one weight axis, `display=swap`.

### If you want it faster

The remaining win is self-hosting Inter (removes the two `preconnect`s and a
render-blocking stylesheet, worth roughly 100–200ms on a cold connection). Subset it
to Latin and `woff2`-only.

## 7. Accessibility

- Skip link to `#main`.
- Contrast: all text meets WCAG AA. The original brand green failed at 2.46:1 on white
  and was darkened for text use — see BRAND.md §1 for the full audit.
- Focus is never suppressed. `:focus-visible` gets a 2px brand outline with offset.
- The mobile menu button carries `aria-expanded` and `aria-controls`; Esc and
  outside-click both close it.
- Scrollspy sets `aria-current` on the active nav link, not just a colour change.
- `aria-busy` on data containers while loading; skeletons are decorative.
- `role="status"` with `aria-live="polite"` on the form result.
- All decorative SVG is `aria-hidden`; the lightbox triggers have explicit labels.
- `prefers-reduced-motion` disables reveals, smooth scrolling and all transitions.

Not yet done: no formal screen-reader pass, and the site has not been tested with
Windows High Contrast Mode.

## 8. Deploying to GitHub Pages

```bash
git remote add origin git@github.com:<user>/<repo>.git
git push -u origin main
```

Then **Settings → Pages → Source: Deploy from a branch → `main` / `(root)`**.

`.nojekyll` is present, which matters: without it GitHub runs the files through Jekyll,
which ignores directories beginning with an underscore and can rewrite files
unexpectedly.

### For a custom domain

1. Add a `CNAME` file at the repo root containing `www.borehamwoodchiropody.co.uk`.
2. Point the DNS `CNAME` for `www` at `<user>.github.io`.
3. Enable **Enforce HTTPS** in the Pages settings once the certificate is issued.

The canonical URLs, `sitemap.xml` and the `og:image` path all already assume
`https://www.borehamwoodchiropody.co.uk/`.

## 9. Known issues and things to check

Ordered by how much they matter.

1. **The address needs confirming.** The original site was internally inconsistent —
   the Contact page said *78* Shenley Road while the Products page and Privacy Policy
   said *76*. Yell and Central Index both list *78*. This build uses **78a**, as
   supplied. It appears in six places: the header utility strip, the contact card, the
   products section, the footer, the JSON-LD block in `index.html`, and the data
   controller clause in `privacy.html`. Grep for `78a` to change them together.
2. **Edwina's HCPC registration number is missing.** The site states she is HCPC
   registered but publishes no number, because the old site never did either. HCPC numbers
   for chiropodists/podiatrists take the form `CHxxxxx`, and `12282` is *not* one — it is
   her Royal College membership number. Ask her for the CH number, then replace the
   HCPC row in the `.creds` panel in `index.html` (search for the `TODO` comment above it)
   and link it to her entry on <https://www.hcpc-uk.org/check-the-register/>. This is the
   one credential a patient can independently verify, so it is worth chasing.
3. **The email address is new.** `info@borehamwoodchiropody.co.uk` did not exist
   anywhere on the original site. **Confirm the mailbox exists and is monitored before
   going live**, or enquiries sent to it will disappear silently.
4. **Opening hours come from the Google Business Profile**, not from the practice
   directly — Mon–Fri 09:30–17:00, closed weekends. Worth confirming with Edwina, and
   they're in `data.js` ready to move to a sheet.
5. **The practitioner portrait is the weakest asset on the site.** `edwina.webp` is
   upscaled from a low-resolution, poorly-lit original and it sits in the About
   section at a size that shows every flaw. One phone photo taken near a window would
   noticeably lift the whole page. This is the single highest-return change available.
6. **The before/after nail images** came from the original site's clinical-study
   section, whose copy attributed the study and testimonial to a US clinic
   (*Betty B., Surfside, FL*). That attribution was dropped as it isn't the practice's
   own patient. The images are captioned as clinical study images. If they are not
   licensed to the practice, replace or remove them.
7. **Testimonials are unattributed beyond a first name and town**, as on the original.
   Fine as-is, but Google reviews would carry more weight if there are any.
8. **The K Laser claims are specific and medical** — "NICE-approved", "no side
   effects", percentages for onychomycosis prevalence. All carried over verbatim from
   the original site. They should be checked against current ASA and CAP guidance for
   health claims before launch; the responsibility sits with the practice, not the site.

## 10. Working on this

There is no build step, no package manager and no dependencies. Edit a file, refresh
the browser.

To serve locally (the `fetch` in `main.js` needs HTTP rather than `file://` once real
sheet URLs are in place):

```bash
python3 -m http.server 8000
```

### Where to make a given change

| Change | File |
|---|---|
| A condition, fee, FAQ or opening time | `assets/js/data.js` |
| Connect a Google Sheet | `assets/js/data.js` — the `url` field |
| A colour, size or spacing value | `assets/css/style.css`, `:root` block |
| Prose in a static section | `index.html` |
| Nav items | `index.html` header + a matching section `id` |
| A new icon for the data layer | the `ICONS` map in `assets/js/main.js` |

### Conventions

- British English in all copy.
- Two-space indentation everywhere.
- Section comments in the CSS use a right-aligned banner; keep them if you add sections.
- Anything rendered from data must go through `esc()`.
- Don't add a dependency. The whole point of this build is that there aren't any.
